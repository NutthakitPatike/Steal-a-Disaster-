# Decisions and unresolved assumptions

- **2026-10-12, confirmed by the Head:** the Head works primarily through ChatGPT + lnwjud MCP; two teammates use Codex. The Head controls product direction and release approval.
- **Current implementation, verified from config:** Luau under `src/` is mapped via Rojo in `default.project.json`. Git stores source; map assets are not in this Rojo mapping. The team still needs to validate the Rojo + Studio workflow on a running toolchain.
- **2026-10-12/13, confirmed by the Head:** Direction A and **Disaster Containment** are the accepted game concept: living collectible Disasters; a deliberate choice between **Stabilize** (slower, safer capture) and **Snatch** (faster, less stable capture); each creature's reaction should affect the escape from an NPC Warden. The familiar Speed/Treadmill/Trail/Zone Index/collection loop supports this core interaction. The Head endorsed the concept, **not final timings, economy, map dimensions, exact reactions, a release date or verified fun**. See [GAME_VISION.md](GAME_VISION.md). The title remains provisional.
- **2026-10-13, confirmed by the Head after team discussion:** the Zone collectible is an original **Disaster Containment Crate**, **not an egg**. A visible-rarity crate spawns randomly in an NPC-guarded Zone; the player uses Stabilize or Snatch and must escape with it, bring it **back to their own base**, then open it to randomly receive one living Disaster **from that crate's rarity pool**. A **Secret crate can produce different Secret Disasters** ranging from less desirable to highly prized. This is a two-stage random loot concept, **not** fixed odds or a commitment to launch Secret tier immediately. Stabilize/Snatch affects escape risk rather than hidden reward odds by default. Crate look and later themes can expand as new Zones are released. See [GAME_VISION.md](GAME_VISION.md) v0.5.
- **2026-10-13, confirmed by the Head (map correction):** the world progresses in a **single long sequential path**: **Zone 1 → Zone 2 → Zone 3 → ...**, adding new Zones further along the same route. The earlier proposed west/east branch portals and separate Event Plaza are superseded. During a new Zone update, **Admin Abuse targets the existing Zone** (e.g. an authorized `/spawn Secret Crate Zone 2` with giveaway/announcement). Command syntax, reward limits and frequency are **not yet specified**. The original sketch's seven rectangles still have no confirmed functions. Review [MAP_CONCEPT.md](MAP_CONCEPT.md) v2 before a Studio map build.
- **2026-10-13, confirmed by the Head:** **Global Event Spawn** replaces the suggested personal **Spawn Event Boost**. Admin Abuse spawning a special crate in a target Zone (e.g. Secret Crate in Zone 2) should broadcast **across all active servers**, where each server spawns its own event crate at a valid Zone spawn node. This is **not** a per-player luck/spawn multiplier, nor a single shared crate across servers. Event quantity, access eligibility, duration, command syntax, reliable catch-up and admin permissions remain for design/implementation; the feature is not live.
- **2026-10-13, confirmed by the Head:** feature direction: **Crate Instability is experimental**; **Warden variants** should expand over updates; **Special Crate Spawn** should exist; **Disaster Synergy** and **Duplicate Progression** are accepted as future directions. Target **weekly game updates**, recurring **Admin Abuse** sessions and meaningful giveaways. Event exact schedule, rarity odds, item amounts, NPC release count and implementation scope are **not fixed**. Live events must be safe for the game's economy and server authority. See [GAME_VISION.md](GAME_VISION.md) Section 8A.
